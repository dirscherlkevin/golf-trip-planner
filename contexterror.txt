Vuln 1: Hardcoded Fallback JWT Secret Key — backend/services/auth.py:9
Severity: High
Category: weak_cryptography / authentication_bypass
Description: The JWT signing secret falls back to the hardcoded string "dev-secret-key-change-in-production" when the SECRET_KEY environment variable is not set. All JWTs — for every user — are signed with this key. An attacker who knows the default (it is publicly visible in the repository) can forge a valid token with an arbitrary sub (user ID) payload.
Exploit Scenario: An attacker clones the repo, reads the fallback value, then crafts a JWT with {"sub": "1", "exp": <future timestamp>} signed with "dev-secret-key-change-in-production". If the production server was deployed without setting SECRET_KEY (easy to miss on a free-tier Render deploy), the forged token passes jwt.decode() validation, returning user ID 1 (typically the first registered account, often the organizer). The attacker now has full authenticated access to every trip that user belongs to, including all member data, budget information, and booking confirmation numbers.
Recommendation: Remove the insecure default entirely. Use SECRET_KEY = os.getenv("SECRET_KEY") and add a startup assertion (if not SECRET_KEY: raise RuntimeError("SECRET_KEY must be set")) so the server refuses to start without it.
